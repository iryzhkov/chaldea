# Mission Control PC canary source
This first slice serves Overview, Agents, Quota and Tokens with the checked Flight/mocr-1969 presentation. Fleet uses official bounded resource observations; Events, Ops and Lab are unavailable pending their approved later consumers. It is source for a later reviewed PC canary, not a fleet deployment.

Run `chaldea mission-control serve --fixture` for synthetic data. Every fixture page says DEMO DATA. Without `--fixture`, the operator opts into the existing local orchestration:read token at the established Chaldea config path and T3 discovery under ~/.t3. This worker never read that token or connected to live T3. No credential minting, write RPC, remote relay or service installation is included.

Only 127.0.0.1 is supported. GET /, fixed scripts/styles, /api/snapshot and /api/events are the entire HTTP interface. Host and Origin checks, Fetch Metadata checks, a restrictive CSP, no CORS and no framing are deliberate. There is no browser bearer, arbitrary file route or RPC proxy. Home Assistant and LAN serving remain future work.

The official pinned WebSocket contract is used exclusively through src/t3/adapter.ts. Shell and per-thread subscriptions wait for synchronized markers, resume cursors on reconnect, rediscover the local origin and abort removed subscriptions. Quiet connected streams stay live. Disconnected streams retain last-known values and observation timestamps. Browser SSE errors or over30seconds without a snapshot invalidate live tiles; their ages advance from the last received heartbeat. Only a fresh snapshot restores browser freshness. Reconciliation prunes all thread cursors against admitted IDs even after child cleanup. Authentication/protocol failures stop the affected subscription rather than retrying indefinitely. Retry delays only reconnect streams; no projection polling exists.

The browser receives selected fields only. Task titles are bounded and suspicious credentials, private paths and emails become Task. Provider aliases, account keys, provider conversation IDs, raw arguments and outputs never leave the process. The approved optional rich projection adds sanitized actual titles/app thread IDs and latest assistant/command summaries; see mission-control-hosted.md for bounds and deployment order. Activity uses the checked tool dictionary; unknown names become Activity unavailable. Target labels are currently omitted because no trustworthy source dictionary is available.

Retention: 48 admitted thread streams and their detail reducers, six activity lines each, eight normalized usage turns per thread, eight SSE clients, 24 HTTP connections and a 128 KiB browser snapshot limit. Removal and snapshot replacement prune details immediately. Full snapshots provide exact total coverage. Ambiguous incremental overflow sets total to unknown and coverage incomplete until another full snapshot, without retaining overflow IDs. Optional detail yields to base rows at both byte limits. Production usage shows retained normalized main-agent turn observations, with input/output totals and cache/reasoning subsets. Live output-counter events are disabled pending provider semantics qualification, so process deltas and rate remain unavailable. Tokens renders the transported retained detail observations with per-field contributor counts and partial coverage; it does not use the legacy process counter. The legacy 512-counter/4096-sample reducer remains for fixtures and a later qualified source; it does not establish production throughput. No cost, daily or lifetime totals are inferred.

Quota reads the existing validated observer cache, watches atomic file replacement, deduplicates known account keys internally, and never invokes a collector or refresh RPC. Unknown, unsupported, error and legitimate zero are distinct. Credits and manual-reset states remain independent. No quota history is fabricated. Host health, exec slots, queue counts, incidents, decisions and shipped counts have no source in this slice.

Flight stylesheet, palettes and fixture data remain byte-for-byte copies; core.css now wraps panel headings and status text and stacks the existing portrait layout at narrow widths; core.js exposes checked helpers, disables automatic cycling and live query-generated agents, boots safely before unavailable renderers are installed, labels unknown waiting duration explicitly, and preserves detail-stream disconnect states on tiles. The new client supplies real DTOs and unavailable views. data.js is preserved as provenance and is never served.

Navigation uses `?mode=overview|agents|agent-summary|tokens|quota|fleet|events|ops|lab`. Existing `mode=agents` URLs open Live threads. Agent summary is a separate view with per-host counts, models, source age and coverage; a fresh zero differs from a host not observed. Live threads keeps idle unsettled threads and hides completed cards 60 seconds after their actual completion; unknown completion times remain visible. Counts and paging use this filtered view, while host coverage, Tokens, Lab and thread details retain the admitted source rows within the 48-row bound. Activity age, source age and unknown state duration remain separate. A missing or unknown mode displays Overview. Tab, picker and number-key selections update the URL while preserving other query parameters and the fragment. Reload and Back/Forward restore that selection; snapshot refreshes and resize do not add history entries. Fleet shows observed CPU/RAM with independent sample age; Events, Ops and Lab remain unavailable pending later consumers. Only the current tab carries the selected class, underline and `aria-current`. Panel headings wrap; the narrow Overview scrolls vertically so lower panels remain reachable. Regression tests execute the shipped core/client scripts, including reduced motion, refresh and history transitions, in `test/unit/mission-control-navigation.test.ts`.
