# Mission Control PC canary source
This first slice serves Overview, Agents, Quota and Tokens with the checked Flight/mocr-1969 presentation. Fleet, Events, Ops and Lab are explicitly unavailable. It is source for a later reviewed PC canary, not a fleet deployment.

Run `chaldea mission-control serve --fixture` for synthetic data. Every fixture page says DEMO DATA. Without `--fixture`, the operator opts into the existing local orchestration:read token at the established Chaldea config path and T3 discovery under ~/.t3. This worker never read that token or connected to live T3. No credential minting, write RPC, remote relay or service installation is included.

Only 127.0.0.1 is supported. GET /, fixed scripts/styles, /api/snapshot and /api/events are the entire HTTP interface. Host and Origin checks, Fetch Metadata checks, a restrictive CSP, no CORS and no framing are deliberate. There is no browser bearer, arbitrary file route or RPC proxy. Home Assistant and LAN serving remain future work.

The official pinned WebSocket contract is used exclusively through src/t3/adapter.ts. Shell and per-thread subscriptions wait for synchronized markers, resume cursors on reconnect, rediscover the local origin and abort removed subscriptions. Quiet connected streams stay live. Disconnected streams retain last-known values and observation timestamps. Browser SSE errors or over30seconds without a snapshot invalidate live tiles; their ages advance from the last received heartbeat. Only a fresh snapshot restores browser freshness. Reconciliation prunes all thread cursors against admitted IDs even after child cleanup. Authentication/protocol failures stop the affected subscription rather than retrying indefinitely. Retry delays only reconnect streams; no projection polling exists.

The browser receives selected fields only. Task titles are bounded and suspicious credentials, private paths and emails become Task. Provider aliases, account keys, T3 IDs, item titles, arguments and output never leave the process. Activity uses the checked tool dictionary; unknown names become Activity unavailable. Target labels are currently omitted because no trustworthy source dictionary is available.

Retention: 48 admitted thread streams, six activity lines each, 512 usage counter baselines, 4096 samples within 60 seconds, eight SSE clients, 24 HTTP connections, 128 KiB snapshot limit. Full snapshots provide exact total coverage. Ambiguous incremental overflow sets total to unknown and coverage incomplete until another full snapshot, without retaining overflow IDs. More threads are reported as truncated. Token totals cover observed deltas since process start, not daily/fleet totals. First live samples count from zero only when the official turn start is at or after this process started. Old/unknown starts and snapshot samples establish baselines; output counter resets are handled. Snapshot seeding retains at most eight running/latest turns per thread and cannot evict live-report baselines. If the 512-entry bound evicts any counter or prevents retention of an incoming snapshot baseline, one scalar timestamp fence records the latest observed/start/update time that could belong to a forgotten counter. Unseen reports count from zero only for official starts strictly after that fence and no later than the present/report time. Other unseen reports rebaseline without producing a measured zero. Known retained deltas remain usable. After eviction, cumulative output and rate remain explicitly partial known lower bounds in Overview and Tokens for this process lifetime; reconnects and fresh turns do not clear that status. No forgotten-ID set is retained. The authenticated canary must qualify whether tokenUsage.outputTokens is cumulative per turn or per request before trusting throughput. This source does not claim that qualification. No cost source or aggregate Slopalytics inference is used. Per-model/history/daily reconciliation is unavailable in this milestone.

Quota reads the existing validated observer cache, watches atomic file replacement, deduplicates known account keys internally, and never invokes a collector or refresh RPC. Unknown, unsupported, error and legitimate zero are distinct. Credits and manual-reset states remain independent. No quota history is fabricated. Host health, exec slots, queue counts, incidents, decisions and shipped counts have no source in this slice.
